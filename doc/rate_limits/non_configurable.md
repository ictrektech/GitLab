GitLab enforces the following rate limits in the application.

| Limit                                | Rate limit                                                     | Details |
|:-------------------------------------|:---------------------------------------------------------------|:--------|
| AI Catalog bulk enable               | 10 requests each minute for each authenticated user                  | Applies to the `aiCatalogItemConsumerBulkCreate` GraphQL mutation, which [enables an agent](../user/duo_agent_platform/agents/custom.md#enable-an-agent) or [flow](../user/duo_agent_platform/flows/custom.md#enable-a-flow) in multiple projects at once. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/265715) in GitLab 19.6. |
| AI Catalog disable                   | 30 requests each minute for each authenticated user            | Applies to the `aiCatalogItemConsumerDelete` GraphQL mutation, which [disables an agent](../user/duo_agent_platform/agents/custom.md#disable-an-agent) or [flow](../user/duo_agent_platform/flows/custom.md#disable-a-flow) in a project or top-level group. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/266155) in GitLab 19.6. |
| AI Catalog enable                    | 30 requests each minute for each authenticated user            | Applies to the `aiCatalogItemConsumerCreate` GraphQL mutation, which [enables an agent](../user/duo_agent_platform/agents/custom.md#enable-an-agent) or [flow](../user/duo_agent_platform/flows/custom.md#enable-a-flow) in a project or top-level group. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/266155) in GitLab 19.6. |
| AI model selection update            | 30 requests per minute per authenticated user                  | Applies to the `aiModelSelectionNamespaceUpdate` GraphQL mutation, which selects the models that GitLab Duo features use in a top-level group on GitLab.com. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/265318) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ai_model_selection_namespace_update_rate_limit`. Disabled by default. |
| Changelog generation                 | 5 calls per minute per user per project                        | Applies to the `:id/repository/changelog` endpoint. The limit is shared between `GET` and `POST` actions. |
| Commit diff files                    | 6 requests per minute                                          | Applies to expanded commit diff files (`/[group]/[project]/-/commit/[:sha]/diff_files?expanded=1`). The limit applies per user for authenticated requests, and per IP address for unauthenticated requests. |
| CSV export                           | 6 requests per minute per authenticated user                   | Applies to exporting issues, work items, merge requests and requirements as CSV, in the UI and through the `workItemsCsvExport`, `mergeRequestsCsvExport` and `exportRequirements` GraphQL mutations. The limit is shared between them. Introduced in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `issuable_csv_export_rate_limit`. Disabled by default. |
| Delete a deployment                  | 500 requests per minute per authenticated user                 | Applies to [deleting a deployment](../api/deployments.md#delete-a-deployment) with `DELETE /projects/:id/deployments/:deployment_id`. Reduces the infrastructure impact of mass deployment deletions. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/243738) in GitLab 19.2. |
| FogBugz import                       | 1 triggered import per minute per user                         | Applies to triggering project imports from FogBugz. Introduced in GitLab 17.6. |
| Group deletion                       | 60 requests per minute per authenticated user                  | Applies to [scheduling a group for deletion](../api/groups.md#schedule-a-group-for-deletion) with `DELETE /groups/:id`. Requests that use `permanently_remove` are limited separately to 10 requests per minute, because they start the deletion immediately. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263606) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `group_and_project_delete_rate_limit`. Disabled by default. |
| GitLab for Slack app events          | 60 requests per minute per Slack workspace                     | Applies to events Slack sends to `POST /integrations/slack/events`, such as mentions and direct messages to GitLab Duo. Requests over the limit are acknowledged and dropped. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/631397) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `slack_app_workspace_rate_limit`. Disabled by default. |
| GitLab for Slack app interactions    | 300 requests per minute per Slack workspace                    | Applies to `POST /integrations/slack/interactions` and `POST /integrations/slack/options`. Requests over the limit are acknowledged and dropped. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/631397) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `slack_app_workspace_rate_limit`. Disabled by default. |
| GitLab for Slack app slash commands  | 60 requests per minute per Slack workspace                     | Applies to `POST /slack/trigger`. Slash commands over the limit are not run and receive an error message. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/631397) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `slack_app_workspace_rate_limit`. Disabled by default. |
| New user accounts                    | 20 calls per minute per IP address                             | Applies to the `/users/sign_up` endpoint. Mitigates attempts to mass discover usernames or email addresses in use. |
| Notification emails                  | 1,000 notifications per 24 hours per project or group per user | Applies to notification emails related to a project or group. [Generally available](https://gitlab.com/gitlab-org/gitlab/-/issues/439101) in GitLab 17.2. |
| Offline transfer exports and imports | 6 requests per minute per user                                 | Applies to [offline transfer](../user/import/gitlab_instances/offline-transfer-migrations.md) exports and imports, which are limited separately. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/209344) in GitLab 19.3. |
| Project deletion                     | 60 requests per minute per authenticated user                  | Applies to [deleting a project](../api/projects.md#delete-a-project) with `DELETE /projects/:id`. Requests that use `permanently_remove` are limited separately to 10 requests per minute, because they start the deletion immediately. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263603) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `group_and_project_delete_rate_limit`. Disabled by default. |
| Repository archives                  | 5 requests per minute per user                                 | Applies to [downloading repository archives](../api/repositories.md#retrieve-file-archive-from-a-repository) through the UI or the API. The limit applies to the project and to the user who starts the download. |
| Repository blob and file access      | 5 calls per minute per object per project                      | Applies to files larger than 10 MB on the [repository blob](../api/repositories.md#retrieve-a-blob-from-a-repository) and [repository file](../api/repository_files.md#retrieve-a-file-from-a-repository) endpoints. [Introduced](https://gitlab.com/gitlab-org/security/gitlab/-/issues/1302) in GitLab 18.1. |
| Snippet creation                     | 300 requests per hour per authenticated user                   | Applies to [creating a snippet](../api/snippets.md#create-a-snippet) with `POST /snippets`, [creating a project snippet](../api/project_snippets.md#create-a-snippet) with `POST /projects/:id/snippets`, and the `createSnippet` GraphQL mutation used by the GitLab UI. The limit is shared between all three. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/251927) in GitLab 19.4. |
| SSH certificate authentication       | 300 failed authentication attempts per minute per IPv4 address or IPv6 `/64` subnet | Applies to SSH certificate resolution by `gitlab-sshd` for certificates whose certificate authority is not in the [`gitlab-sshd` `config.yml`](../administration/operations/gitlab_sshd_ssh_certificates.md). Only failed resolutions count toward the limit. When an address or subnet is over the limit, all certificate resolution requests from that address or subnet are rejected until the one-minute window expires. If GitLab Shell does not send a valid client IP address, the limit uses the GitLab Shell node address. IP addresses in the [failed authentication ban allowlist](https://docs.gitlab.com/omnibus/settings/configuration/#configure-a-failed-authentication-ban) are exempt. An allowlisted IPv6 address does not exempt the rest of its `/64` subnet. If the fallback GitLab Shell node address is in the allowlist, the limit does not apply. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263054) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ssh_certificate_authentication_rate_limit`. Disabled by default. |
| Update username                      | 10 calls per minute per authenticated user                     | Limits how frequently a username can be changed. Mitigates attempts to mass discover which usernames are in use. |
| Username exists                      | 20 calls per minute per IP address                             | Applies to the internal `/users/:username/exists` endpoint, which checks whether a chosen username is taken. |
| Work item bulk update                | 30 requests per minute per authenticated user                  | Applies to [bulk editing issues](../user/project/issues/managing_issues.md#bulk-edit-issues) and [epics](../user/group/epics/manage_epics.md#bulk-edit-epics) in the UI, and to the `workItemBulkUpdate` GraphQL mutation. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263775) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `work_item_bulk_update_rate_limit`. Enabled by default. |
| Work item deletion                   | 300 requests per minute per authenticated user                 | Applies to the `workItemDelete` GraphQL mutation. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/253621) in GitLab 19.4. [Generally available](https://gitlab.com/gitlab-org/gitlab/-/work_items/628006) in GitLab 19.5. |
| Work item hierarchy reorder          | 120 requests per minute per authenticated user                 | Applies to [reordering child items](../user/work_items/child_items.md#reorganize-child-items) in the UI, and to the `workItemsHierarchyReorder` and `epicTreeReorder` GraphQL mutations. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263802) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `work_item_hierarchy_reorder_rate_limit`. Enabled by default. |
