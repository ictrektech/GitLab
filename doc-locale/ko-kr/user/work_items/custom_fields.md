사용자 정의 필드는 이슈 및 에픽과 같은 작업 항목에 특화된 정보를 추가하여 특정 계획 요구 사항과 일치합니다. 그룹에 대한 사용자 정의 필드를 구성하여 비즈니스 가치, 위험 평가, 우선 순위 순위 또는 팀 속성과 같은 데이터 포인트를 추적합니다. 이 필드는 그룹, 하위 그룹 및 프로젝트 전체의 모든 작업 항목에 표시됩니다.

사용자 정의 필드는 팀이 전체 워크플로 전체에서 정보를 기록하고 보고하는 방법을 표준화하는 데 도움이 됩니다. 이 표준화는 프로젝트 전체에서 일관성을 만들고 더 강력한 필터링 및 보고 기능을 지원합니다. 다양한 데이터 요구 사항 및 계획 시나리오에 맞게 다양한 필드 유형 중에서 선택합니다:

- 단일 선택
- 다중 선택
- 숫자
- 텍스트

## 그룹에 대한 사용자 정의 필드 구성 {#configure-custom-fields-for-a-group}

최상위 그룹에 대한 사용자 정의 필드를 구성하여 해당 그룹, 하위 그룹 및 프로젝트의 작업 항목에 대해 사용 가능하게 합니다.

### 사용자 정의 필드 만들기 {#create-a-custom-field}

팀이 추적해야 하는 특정 정보를 캡처하기 위해 사용자 정의 필드를 만듭니다. 조직의 요구 사항에 맞게 워크플로를 조정하여 하나 이상의 작업 항목 유형에 대해 각 필드를 구성할 수 있습니다.

다음 제한 사항을 염두에 두십시오:

- 최상위 그룹은 최대 50개의 활성 사용자 정의 필드를 포함할 수 있습니다.
- 작업 항목 유형은 최대 10개의 사용자 정의 필드를 할당할 수 있습니다.

사전 요구 사항:

- 그룹의 관리자 또는 소유자 역할을 보유해야 합니다.

사용자 정의 필드를 만들려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 그룹을 찾습니다. 이 그룹은 최상위 수준이어야 합니다.
1. 왼쪽 사이드바에서 **Settings** > **Work items**를 선택합니다.
1. **필드 생성**을 선택합니다.
1. 필드를 완성합니다:
   - **유형**에서 필드의 유형을 선택합니다:
     - 단일 선택
     - 다중 선택
     - 숫자
     - 텍스트 필드

     필드를 만든 후 필드 유형을 변경할 수 없습니다.
   - **사용 대상**에서 이 필드를 사용 가능하게 할 작업 항목 유형을 선택합니다.
   - **옵션**(단일 선택 및 다중 선택 필드)에서 가능한 선택 옵션을 입력합니다. 단일 선택 또는 다중 선택 필드는 최대 50개의 선택 옵션을 가질 수 있습니다.
     - 각 옵션의 왼쪽에 있는 그립 아이콘({{< icon name="grip" >}})을 드래그하여 옵션을 재정렬합니다.
     - 한 번에 여러 옵션을 추가하려면 입력을 선택하고 항목 목록을 붙여넣으면 각 항목이 한 줄씩 표시됩니다.
1. **저장**을 선택합니다.

### 사용자 정의 필드 편집 {#edit-a-custom-field}

조직의 변화하는 요구 사항을 반영하기 위해 기존 사용자 정의 필드를 편집합니다. 기존 데이터를 잃지 않고 필드의 이름, 적용되는 작업 항목 유형 및 사용 가능한 옵션을 수정할 수 있습니다.

사전 요구 사항:

- 그룹의 관리자 또는 소유자 역할을 보유해야 합니다.

사용자 정의 필드를 편집하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 그룹을 찾습니다. 이 그룹은 최상위 수준이어야 합니다.
1. 왼쪽 사이드바에서 **Settings** > **Work items**를 선택합니다.
1. 편집할 필드 옆에서 **편집 `<field name>`**({{< icon name="pencil" >}})을 선택합니다.
1. 필드 중 하나를 변경합니다.
1. **업데이트**를 선택합니다.

### 사용자 정의 필드 아카이빙 {#archive-a-custom-field}

더 이상 필요하지 않은 사용자 정의 필드를 아카이빙하면서 과거 데이터를 보존합니다. 아카이빙하면 이 필드가 있던 모든 작업 항목에서 필드가 제거됩니다.

사전 요구 사항:

- 그룹의 관리자 또는 소유자 역할을 보유해야 합니다.

사용자 정의 필드를 아카이빙하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 그룹을 찾습니다. 이 그룹은 최상위 수준이어야 합니다.
1. 왼쪽 사이드바에서 **Settings** > **Work items**를 선택합니다.
1. 아카이빙할 필드 옆에서 **아카이브 `<field name>`**({{< icon name="archive" >}})을 선택합니다.

### 사용자 정의 필드 아카이브 해제 {#unarchive-a-custom-field}

다시 사용해야 할 때 이전에 아카이빙된 사용자 정의 필드를 복원합니다. 이 필드에 대한 값이 설정된 작업 항목은 필드가 아카이빙되기 전에 가진 동일한 값을 유지합니다.

사전 요구 사항:

- 그룹의 관리자 또는 소유자 역할을 보유해야 합니다.

사용자 정의 필드를 아카이브 해제하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 그룹을 찾습니다. 이 그룹은 최상위 수준이어야 합니다.
1. 왼쪽 사이드바에서 **Settings** > **Work items**를 선택합니다.
1. **아카이빙됨**을 선택하여 아카이빙된 필드를 나열합니다.
1. 아카이브 해제할 필드 옆에서 **아카이브 해제 `<field name>`**({{< icon name="redo" >}})을 선택합니다.

## 작업 항목에 대한 사용자 정의 필드 값 설정 {#set-custom-field-values-for-a-work-item}

그룹에 대해 구성된 사용자 정의 필드를 사용하여 작업 항목에 관련 정보를 추가합니다.

사전 요구 사항:

- 작업 항목의 프로젝트 또는 그룹에 대해 플래너, 리포터, 개발자, 관리자 또는 소유자 역할을 보유해야 합니다.
- 게스트 역할이 있는 경우 작업 항목을 만들 때만 사용자 정의 필드를 설정할 수 있습니다.

1. 작업 항목으로 이동합니다.
1. 오른쪽 사이드바에서 편집할 사용자 정의 필드의 섹션을 찾은 다음 **편집**을 선택합니다.
1. 원하는 값을 입력하거나 선택합니다.
   - 텍스트 필드 값은 최대 1024자를 포함할 수 있습니다.
1. 필드 외부의 아무 영역을 선택합니다.

## 필드 유형 선택 가이드 {#field-type-selection-guide}

사용자 정의 필드를 만들 때 추적하려는 데이터의 종류와 일치하는 필드 유형을 선택합니다. 올바른 필드 유형은 데이터 품질을 개선하고 보고를 더 효과적으로 만듭니다.

### 단일 선택 필드 {#single-select-fields}

다음의 경우 단일 선택 필드를 사용합니다:

- 사용자가 미리 정의된 목록에서 정확히 하나의 옵션을 선택해야 합니다.
- 옵션은 상호 배타적입니다.
- 일관성을 강제하고 자유형 입력을 방지하려고 합니다.

단일 선택 필드는 다음에 적합합니다:

- 우선 순위 표시기(예: `High`, `Medium`, `Low`)
- 카테고리 할당
- 팀 할당
- 승인 상태
- 우선 순위 수준

### 다중 선택 필드 {#multi-select-fields}

다음의 경우 다중 선택 필드를 사용합니다:

- 여러 값이 동시에 적용될 수 있습니다.
- 겹치는 속성을 추적해야 합니다.
- 항목이 여러 범주에 속할 수 있습니다.

다중 선택 필드는 다음에 적합합니다:

- 태그 또는 레이블
- 필요한 기술
- 영향을 받는 구성 요소
- 이해 관계자 그룹
- 기능 기능

### 숫자 필드 {#number-fields}

다음의 경우 숫자 필드를 사용합니다:

- 정량적 데이터를 수집해야 합니다.
- 계산 또는 집계를 수행하려고 합니다.
- 정보를 숫자로 정렬해야 합니다.

숫자 필드는 다음에 적합합니다:

- 비용 예상
- 시간 추정
- 비즈니스 가치 점수
- 순위 또는 우선 순위 점수
- 완료 비율

### 텍스트 필드 {#text-fields}

다음의 경우 텍스트 필드를 사용합니다:

- 미리 정의된 범주에 맞지 않는 고유한 정보를 캡처해야 합니다.
- 데이터는 매우 가변적입니다.
- 컨텍스트나 세부 정보를 제공해야 합니다.

텍스트 필드는 다음에 적합합니다:

- 추가 컨텍스트
- 외부 참조 ID
- 연락처 정보
- 간단한 메모 또는 댓글
- URL 또는 링크

## 사용자 정의 필드에 대한 명명 규칙 {#naming-conventions-for-custom-fields}

사용자 정의 필드에 대한 일관된 명명 규칙을 사용하면 이해하고 사용하기가 더 쉬워집니다. 좋은 필드 이름은 도입 및 데이터 품질을 개선합니다.

### 일반 지침 {#general-guidelines}

- 이름을 간단하지만 설명적으로 유지합니다.
- 조직이 이해하는 명확하고 구체적인 언어를 사용합니다.
- 대문자 사용에 일관성을 유지합니다(제목 사례 권장).
- 널리 알려지지 않은 경우 약어를 피합니다.
- 해당하는 경우 측정 단위를 포함합니다.

### 단일 선택 및 다중 선택 필드 이름 지정 {#naming-single-select-and-multi-select-fields}

카테고리 이름으로 시작한 다음 설명자를 따릅니다. 예를 들어:

- `Risk Level` `Risk` 대신
- `Customer Segment` `Segment` 대신
- `Development Phase` `Phase` 대신
- `Approval Status` `Status` 대신

### 숫자 필드 이름 지정 {#naming-number-fields}

필드 이름에 측정 단위를 포함합니다. 예를 들어:

- `Effort Points` `Points` 대신
- `Budget Estimate ($)` `Budget` 대신
- `Implementation Time (days)` `Time` 대신
- `Business Value Score` `Value` 대신

### 텍스트 필드 이름 지정 {#naming-text-fields}

입력해야 하는 정보를 명확하게 표시합니다. 예를 들어:

- `External Reference ID` `Reference` 대신
- `Implementation Notes` `Notes` 대신
- `Requirements Source` `Source` 대신

### 팀 특정 접두사 {#team-specific-prefixes}

여러 팀이 동일한 GitLab 인스턴스를 사용하는 경우 혼동을 피하기 위해 팀 접두사를 추가하는 것을 고려합니다:

- `DEV: Sprint Priority`
- `QA: Test Environment`
- `UX: Design Status`
- `PM: Market Segment`

이 접근 방식은 팀이 해당 작업과 관련된 필드를 빠르게 식별하는 데 도움이 됩니다.
